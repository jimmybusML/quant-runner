# M8 直接交锋 Crown AH 残差迁移

状态：已执行；研究回放，不是正式策略。执行日：2026-11-19。

## 假设与查重

检验同联赛、同两支球队过往交锋的 Crown AH 结算残差，能否在场地互换后预测目标比赛的覆盖方向。该机制区别于 R26–R30 一般球队强弱/攻防/射门残差，R39–R45 对手邮件或ID交互，以及 R44–R46 的排名、日历和赛程环境；A–L 的 I/K 和 M1–M8 则是普遍 Crown 路径/收益模型。本研究使用双方身份和直接对赛关系，但此前交锋的盘口覆盖残差属于球队对特定对手的历史合同表现。

每个目标比赛只使用严格早于其 UTC 开球、同一联赛、同一球队对的历史赛事；相同开球时刻不使用。以全部先前交锋平均覆盖残差决定方向，另保存仅取最近一次交锋的版本。任何目标赛果或未来冻结八组成分不进入信号。目标 FID 属于冻结八组时从新增订单剔除。过往 Crown end-line 不是经逐场实际 HTTP receipt 证明的历史收件报价，因此全历史结果均为 event-time 回放，不能称为实时可知信号。

## 数据和结算

- 39,101 条 Crown AH 路径与独立赛事/FT/球队身份记录严格按 FID 联接；未发现赛事身份冲突。冻结八组为 10,294 个唯一 FID。
- 历史 Crown 报价线及主客赔率逐腿结算；四分之一盘拆为两个半注，客队使用反号盘口。H2H 主队相对残差在场地互换时同步反向。
- 另对两种历史候选共 45,044 条有方向订单独立重算 AH 收益，逐条与逐场文件一致，结算差异为0。
- 逐场主/客收益、信号、此前交锋列表、FID、比赛日期及结算存入 `h2h_candidate_orders.jsonl`。输入 SHA、方法、逐年和逐周数据在 `h2h_results.json`。

## 已审计真实赛前 Crown 收据

将信号按 FID 与独立审核的 1,230 条真实赛前 HTTP 收据档案连接；限定 `received_utc < kickoff_utc`、raw 与 snapshot SHA、可信 FT，并移除 8 个报价错配 FID。不以其他来源或邻近盘口补价。结算为 **559 场、−31.510U / −5.637% / MDD 44.885U**；同 559 FID 的盘口 favorite 为 −39.680U。脚本逐阶段留有排除计数：报价错配8、无可联接赛事身份/比分/H2H特征行306、冻结八组交集245、无既往同联赛交锋97、H2H残差无方向15；另559符合候选方向。逐周（W41–W45）分别为 121/−10.470、126/−16.955、134/−3.440、164/−1.710、14/+1.065。此收据档案已参与前轮研究设计，属于历史收据回放，不是新数据或锁定前瞻验证。缺少信号生成时的实际收件证明及成交记录，故不能将相对 favorite 的较少亏损解释成可执行的正收益。

## 结论与边界

直接交锋残差没有解释原八组优势，也没有提供独立正收益；它在 2024、2026 显著亏损，2025 仍亏。对赛身份和历史结果可用于时间排序，但历史 Crown 盘口首次发布时间/收到时间没有逐场存档。真实收据只有 559 个有信号 FID，且来自此前已使用的六周窗口。故本实验同时不支持盈利、也不足以证明“过去盘口残差”当时可获得。
