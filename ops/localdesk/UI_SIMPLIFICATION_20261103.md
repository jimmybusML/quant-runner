# Mac 本机控制台界面减法｜2026-11-03

## 用户本轮要求和已完成实现

- 用户不理解原始技术日志、文件 hash/代码信息，要求去掉英文和无关字符，首页优先呈现所有模型的真实战绩，能够点击看到 M1/MR1 的全部、上周、本周胜负、未结单及 ROI；M3 按三套模型×AH/OU 拆开；M4 明确展示与 MR1 基础的历史联赛优化研究，不冒充已经正式派单。
- Mac `~/QuantAsiaDesk/web/index.html` 已替换为精简页面，三个入口：**战绩／运行／设置**。默认首页就是战绩，移除了代码版本号/复杂开发状态；“运行”页按模型只有运行一次、结算赛果、看战绩等操作，“设置”页每模型自己的定时与 TG 开关。代码未修改任何预测模型或盘口规则。
- M1/MR1 周绩效由新的 `display_data.py` **直接读取真实 TG SENT 收据和正式 settlement**，按北京时间 TG sent_at 的自然周：M1 AH 截本轮正式账本累计发402、结394、待8、-3.705U；上周66发65结 +5.300U；本周8发7结 -2.770U。MR1 AH 累计574发557结17待 -18.625U；上周269发266结 -22.640U；本周22发8结 -4.460U。所有盈亏/ROI按已结订单1U等额统计，其他 OU/AI/影子订单不混。
- M3 由已去重的 `m3_latest.json` 显示 3 模型×2 盘口六条独立影子结果（目前1530有效模拟、1050结、+0.275U）；M4 显示 MR1 历史原方案与剔除土超/J1 的反事实对比，**不是正式实战成绩**。界面不冒充 M4 已有独立前瞻选单器。
- `job_explain.py` 将原进程输出转换为中文结果（扫描发现多少预测、赛果新补多少、TG 确认发几条、是否失败），原始日志保留但默认折叠在“技术详情”，避免技术术语干扰用户。旧任务也在读取时生成简短中文摘要，不篡改原始日志。
- 设置页明确解释：指定时间=每天到点运行如 06:00、12:00；循环间隔=每隔 N 分钟运行。查看已有战绩**不需要 API/TG 密钥**，只在联网扫描/补采和发送 TG 时需要；账号填写折叠于“连接设置”。不要求创建任何新 GitHub 仓库或 token。
- M3/M4 原先“正式 TG 未开放”硬编码已删除。现在用户可自主勾选 `tg_enabled`，默认仍为 false；`research_notify.py` 仅当已开启、该次模型成功运行、有研究 TG 凭证时发送：M3 **当次真正产生的影子模型预测**逐单推送，M4 **现有历史联赛研究报告**推送（M4 无独立正式前瞻策略，不能假装下正式单）。TG 研究推送用独立 receipt book，记录 SENT/UNKNOWN，不把研究推送当作 M1/MR1 正式订单或重新计战绩；未擅自增加 EV、数量或联赛筛选门槛。
- 用户现在可按各模型自己控制 TG 开关；真实 TG 推送尚未进行，因为本机尚未设置 TotalCorner 和 TG 凭证，本轮也未擅自启用任何自动运行或 TG。M3/M4 研究通知可选独立 TG 账号。M1/MR1 正式推送仍使用各自原发送器。

## 接续

真实本机扫描、TG 新通知、账本回写须在用户自己于本机「设置→连接设置」保存已有赛事数据密钥 / 相应 TG 账号后按既有原模型逻辑验证。用户有权决定是否将 M3/M4 改为正式生产，但现在 M3 仅有影子预测，M4 仅有 MR1 历史反事实研究；独立正式策略需要用户进一步确定，不得自动把历史研究报告当新正式订单。
